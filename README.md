# tofu-modules

OpenTofu modules of dreitier's infrastructure, used by the Terragrunt units of
[dreitier/basement](https://github.com/dreitier/basement) (private). One directory per module under
[`modules/`](modules), each versioned and released on its own.

## Using a module

basement pins every module by its tag `<module>@<version>` in `config/modules.hcl`:

```hcl
terraform {
  source = "git::https://github.com/dreitier/tofu-modules.git//modules/fintier?ref=fintier@1.0.0"
}
```

To try a change before it is released, point basement at a local checkout or a branch
(`TG_MODULES_ROOT` / `TG_MODULES_REF`, see `config/modules.hcl` in basement).

Every module has a `README.md`: description by hand, inputs and outputs generated by
[terraform-docs](https://terraform-docs.io/) (`.terraform-docs.yml`) between the `BEGIN_TF_DOCS`/`END_TF_DOCS`
markers.

## Releases

[multi-semantic-release](https://github.com/anolilab/semantic-release/tree/main/packages/multi-semantic-release)
through the shared action
[`dreitier/shared-ci-components/multi-semantic-release`](https://github.com/dreitier/shared-ci-components)
(`.github/workflows/release.yml`): on every push to main the Conventional Commits that touch
`modules/<module>/` since the module's last tag decide its next version – tag `<module>@x.y.z`,
`modules/<module>/CHANGELOG.md`, GitHub release, committed by dreitier-release-bot.

- PRs are squash-merged, the PR title is the commit message (checked by `pr-title / Conventional Commit`).
- `feat` → minor, `fix`/`perf`/`build(deps)` → patch, `feat!`/`BREAKING CHANGE` → major. A PR that touches
  several modules releases each of them with the same type.
- `npm` is only the workspace manifest for multi-semantic-release: root `package.json` (`workspaces`) and one
  `package.json` per module (`name` = directory, `version` stays `0.0.0` – the tags are the versions).

## New module

1. `modules/<name>/` with `main.tf` (leading comment = what the module does), `variables.tf`, `outputs.tf`,
   `versions.tf` (`required_version` and every provider with a version constraint).
2. `modules/<name>/package.json`: `{ "name": "<name>", "version": "0.0.0" }` – without it the module is never
   released.
3. `modules/<name>/README.md`: `# <name>`, a description, then the markers
   `<!-- BEGIN_TF_DOCS -->` / `<!-- END_TF_DOCS -->` – pre-commit fills them.
4. PR titled `feat(<name>): …` → first release `<name>@1.0.0`.

## Development

```bash
pre-commit install          # tofu fmt, tflint, trivy, terraform-docs, actionlint, file checks
pre-commit run --all-files
```

Needs `tofu`, `tflint` and `trivy` on PATH (versions: `.tool-versions`, `.github/workflows/ci.yml`). CI
(`ci.yml`) runs the same hooks plus `tofu init -backend=false && tofu validate` (and `tofu test` where a module has
`tests/*.tftest.hcl`) for the modules a PR changes. Dependencies: Renovate (`renovate.json`, workflow
`renovate.yaml`, org-owned Renovate GitHub App like basement).

Rules for module code (from basement): no secrets in the state – credentials via `ephemeral` resources,
generated secrets through write-only attributes (`*_wo`); stateful resources keep `prevent_destroy`.
